## Difficulty of a finding

Every finding is marked `easy`, `medium`, `hard`.

## Limits this audit uses

- More than 20 connectors in one session is a finding.
- 10 or more scheduled tasks on one account is a finding.

## Figures to watch

- Hours returned each week on named tasks
- Usage spent per finished task
- Processes that run without a person starting them

## Modules and steps

### `check`: Quick check

Outcome: A list of findings, each marked easy, medium or hard, and the order to fix them in. About 10 minutes. Steps are in `../setup-check/references/check.md`, part of the `setup-check` skill.

- `check.session` See what is loaded in a normal session: connectors, tools and skills
- `check.workspace` Count projects, plugins, org skills and scheduled tasks
- `check.team` Ask about usage limits, onboarding, permissions and spend
- `check.findings` Agree the findings and what to fix first

### `foundations`: Foundations

Outcome: A company context file, tidy projects, one page of usage rules and a way to bring people on. About 45 minutes. Steps are in `../workspace-foundations/references/foundations.md`, part of the `workspace-foundations` skill.

- `foundations.context` Write and install the company context file
- `foundations.projects` Merge tiny projects and take changing data out of project files
- `foundations.rules` Write the usage rules, set approvals for write actions and a spend cap
- `foundations.onboarding` Name a champion, plan 1:1 sessions and choose the first skill people start on

### `skills`: Skills from your experts

Outcome: One skill built from a senior person's own method, an owner for it and a ranked list of the next ones. About 50 minutes. Steps are in `../sop-to-skill/references/skills.md`, part of the `sop-to-skill` skill.

- `skills.inventory` List the skills and plugins you have, where each came from and which ones clash
- `skills.sops` List the core procedures by team and the senior person who knows each best
- `skills.build` Turn one procedure into a working skill and test it on a second example
- `skills.ownership` Name the owner, the update route and the next skills to build

Hard part, needs someone technical: Organising many skills into plugins for each team, kept up to date from one place.

### `connectors`: Connectors

Outcome: A table of what Claude can read and change, unused access closed, and the heaviest connectors named. About 40 minutes. Steps are in `../connector-review/references/connectors.md`, part of the `connector-review` skill.

- `connectors.inventory` List every connector and how many load in a normal session
- `connectors.access` Note what each one can read and change, and close what nobody needs
- `connectors.weight` Test your top three services: how much comes back and how much is used
- `connectors.plan` Record which connectors to trim, keep or replace

Hard part, needs someone technical: Replacing heavy general connectors with custom ones for your top services, behind one entry point.

### `processes`: Work that runs without you

Outcome: The first process to automate, written as a spec someone can build from. About 35 minutes. Steps are in `../process-finder/references/processes.md`, part of the `process-finder` skill.

- `processes.schedules` Count scheduled tasks and the recurring work a person still has to start
- `processes.limits` Find who hits usage limits and what causes it
- `processes.pick` Rank the candidates and pick the first
- `processes.spec` Write the spec: trigger, inputs, steps, checks and owner

Hard part, needs someone technical: Building the process outside the chat and trusting it to run on its own.

### `plan`: Plan and seats

Outcome: A plan recommendation with the reasons written down. About 20 minutes. Steps are in `references/plan.md`.

- `plan.needs` Count users by role and list the admin and security controls you need
- `plan.cost` Compare the cost of each plan for your seat count
- `plan.decision` Record the decision and what would change it

### `fit`: Right tool for the work

Outcome: A map of your team's work against the assistant that suits it, and a two-week test. About 20 minutes. Steps are in `references/fit.md`.

- `fit.work` Describe the work by role and where its material lives
- `fit.match` Match each kind of work to an assistant
- `fit.decision` Record the decision and the test that would confirm it

### `content`: Content from real work (optional)

Outcome: A brand voice file and a first piece written from work your experts actually did. About 35 minutes. Steps are in `../brand-voice/references/content.md`, part of the `brand-voice` skill.

- `content.voice` Write the brand voice file from examples you are happy with
- `content.sources` List the real work and the experts that content should come from
- `content.piece` Write a first piece from one real job
- `content.publish` Agree who checks it and how it gets published

Hard part, needs someone technical: Publishing straight to your website or its content system.

Step statuses: `done`, `skipped`, `blocked`.
