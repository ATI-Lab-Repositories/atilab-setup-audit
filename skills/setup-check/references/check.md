# Quick check

_Generated from the course source. Do not edit this file by hand._

Outcome: A list of findings, each marked easy, medium or hard, and the order to fix them in. About 10 minutes.

This is a ten-minute diagnosis. It fixes nothing. It looks at what loads into a normal session, counts a few things in the workspace, asks a handful of questions about the team, and ends with a list of findings and the order to deal with them.

Keep it fast. Most questions need a number, a yes or a no. "I do not know" is a valid answer: record it and move on. Do not start fixing anything in this module, even if the fix is obvious.

Three words to explain once, the first time each comes up:

- A **connector** links Claude to another service, such as email, a shared drive or a CRM, so Claude can read from it and sometimes change things in it.
- A **skill** is a small folder of written instructions that Claude loads when a matching task comes up.
- A **plugin** is a package that bundles skills, and sometimes connectors, so a team gets them together.

Menu names in Claude's apps are changing. When this module was written, "Customize" was being renamed "Plugins", and chat and Cowork were being merged into one experience. If what the person sees does not match a menu name below, follow these pages instead:

- Connectors and tool access: https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities
- The Plugins page: https://support.claude.com/en/articles/17740565-manage-plugins-skills-and-connectors-from-one-plugins-page
- Scheduled tasks: https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork

## check.session: See what is loaded in a normal session: connectors, tools and skills

### Ask

Ask nothing at first. Look at your own session and report what you see. Only then ask:

1. "Is this what a normal working session looks like for you, or do you usually have more or fewer connectors switched on?"
2. Only if you count more than 20 connectors: "In the message box, open **+**, then **Connectors**, then **Tool access**. Is it set to Auto, On demand or Always available?"

If you cannot see your own list of tools and skills, say so and ask instead: "Open **+** in the message box and hover over **Connectors**. How many are switched on?" and "Roughly how many skills do you have switched on?"

### Do

- List what is available to you in this session, from your own tool and skill list: each connector by the service it belongs to, a rough count of the tools they expose in total, and the skills and plugins you can see.
- Do not ask the person to read their settings for this. Do not search past chats or memory. Do not call any connector to read data. You are only reading the list of what is loaded.
- Tell the person in three lines: how many connectors, roughly how many tools, how many skills.
- Compare the connector count with the limit this audit uses: more than 20 connectors in one session is a finding. Every connector adds its tool descriptions to the session, and each call adds whatever it returns. Too many at once crowds the session and uses up the person's allowance faster.
- Anthropic's own help page suggests switching **Tool access** to **On demand** from about ten active connectors. Note the setting if you asked for it.
- What you see is this person's session only. Colleagues may have a different set. Say so.

### Done when

- The number of connectors, a rough number of tools and the number of skills are written down.
- The person has said whether this is a normal session for them.

### Mark blocked when

- You cannot see your own tool list and the person cannot open the connectors menu in this session.

### Summary to report

State the counts and whether the connector count is over the limit. No service names. Example: "A normal session loads 24 connectors, about 180 tools and 9 skills. That is over the 20-connector mark; tool access is set to Auto."

## check.workspace: Count projects, plugins, org skills and scheduled tasks

### Ask

One at a time. A rough number is enough.

1. "Are you an owner or admin of your Claude organisation, or a member?"
2. "Open **Projects**. Roughly how many projects are there, and how many of them hold only a file or two?"
3. "Do any project files hold numbers or lists that change, such as monthly figures, current targets or this week's tasks? Yes or no."
4. "How many plugins are installed? None is a fine answer."
5. "How many skills has the company provided to everyone, and does someone look after them?" A member sees these under **Organization skills**. An owner sees them under **Organization settings**, on the page for plugins and skills.
6. "Open **Scheduled** in the left sidebar. How many scheduled tasks do you have? And across the team, is it a handful or dozens?"

### Do

- Record each answer in one line. Write "not known" where the person cannot tell.
- If you could already see skills and plugins in the session step, use those counts and only ask what you could not see.
- Compare scheduled tasks with the limit this audit uses: 10 or more scheduled tasks on one account is a finding. It means recurring work is piling up inside one person's Claude and it is time to move it into automations that run on their own.
- The person sees only their own scheduled tasks. The team figure is their estimate. Record it as an estimate.
- Do not open, read or change any project, skill or task.

### Done when

- Each of the six questions has a number, a yes or no, or "not known".

### Mark blocked when

- The person cannot open Claude's menus in this session at all, for example because they are answering from a phone without the app. Give them the six questions to take away.

"Not known" is not a blocker. Record it and continue.

### Summary to report

State the counts. Example: "About 40 projects, most with one or two files; changing figures kept in project files. No plugins. 6 company skills with no clear owner. 14 scheduled tasks on one account."

## check.team: Ask about usage limits, onboarding, permissions and spend

### Ask

One at a time. Short answers.

1. "Does anyone hit usage limits? Which roles, and how often: daily, weekly, rarely?"
2. "Have you bought more seats or extra usage because of that? Yes or no."
3. "Of the people who have a seat, roughly how many use Claude every week: most, about half, a few?"
4. "How did people get started: training, one person who helps the others, one-to-one sessions, or nothing organised?"
5. "Can Claude send, change or delete things in your connected services without a person approving each time? Yes, no or not known."
6. "Is there a monthly cap on extra spending? Yes, no or not known."

If the person brings up marketing, content or being found online at any point, note it. Do not ask about it.

### Do

- Record each answer in one line, with roles and not names.
- Do not explain causes or fixes yet. That comes in the next step.

### Done when

- Each of the six questions has an answer or "not known".

### Mark blocked when

- The person knows only their own use and someone else holds the team picture. Record what they know, give them the questions for the other person, and mark the step `blocked`.

### Summary to report

State the answers in general terms. Example: "Three heavy users hit limits weekly; extra seats were bought. About half the team uses it each week. No organised onboarding. Write actions run without approval. No spend cap."

## check.findings: Agree the findings and what to fix first

### Ask

- "Here are the findings. Does anything look wrong, or is anything missing that bothers you day to day?"
- "This is the order I suggest. Do you agree, or would you start somewhere else?"
- Only if the person brought up marketing, content or visibility: "There is an optional module on content written from your team's real work. Do you want to add it at the end?"

### Do

Turn the answers from the first three steps into a findings table. Use only findings the answers support. Do not pad the list.

| Finding | Why it matters | Difficulty | Module that deals with it |
| --- | --- | --- | --- |

Mark each finding with one difficulty:

- **easy**: the person can fix it with you during this audit.
- **medium**: the person can do it with some time and comfort with settings or simple tools, or with a little help.
- **hard**: it needs someone technical to build it.

Use this guide. The first column is what you heard or saw.

| What you found | Finding | Difficulty | Module |
| --- | --- | --- | --- |
| More than 20 connectors in a normal session | Too many connectors load at once and crowd the session | easy | `connectors` |
| People hit limits and work goes through general-purpose connectors for the main services | Connectors probably return far more than the work needs | hard to fix, easy to confirm | `connectors` |
| Claude can change things without approval, or nobody knows | Write actions are not controlled | easy | `connectors`, `foundations` |
| No company context file | Everyone re-explains the company, or gets generic answers | easy | `foundations` |
| Many projects with one or two files | Shared background is duplicated and drifts apart | easy | `foundations` |
| Changing figures or task lists in project files | Claude treats stale numbers as true | easy | `foundations` |
| No usage rules or no spend cap | Nobody knows what is allowed; spending has no ceiling | easy | `foundations` |
| Few people use it weekly and nothing organised to start them | Adoption has stalled | easy | `foundations` |
| No skills, or mostly skills copied from online libraries | The team's own methods are not captured | easy | `skills` |
| Skills with no owner, no plugins, or standalone skills that overlap with skills inside plugins | Skills are disorganised and can clash | medium | `skills` |
| 10 or more scheduled tasks on one account, or much recurring work started by hand | Work that should run on its own still depends on one person's Claude | medium to hard | `processes` |
| People hit limits and seats or extra usage were bought | The cause is usually how the work is set up, not the number of seats | medium | `processes`, `connectors` |
| The plan or seat count is in question | Plan decision is open | easy | `plan` |
| Unsure whether Claude is the right assistant for some work | Tool fit is open | easy | `fit` |

Then:

1. Show the table with the person's own findings only.
2. Say this plainly, once: the easy fixes are worth doing and give a modest improvement. The larger gains usually come from the medium and hard findings, and the hard ones need someone technical. This audit will do the easy ones with the person and write down exactly what the hard ones involve.
3. Propose the order of the modules. Start from the default order of this run; if there is no set order, put the modules with the most findings first. Move a module earlier only when the findings clearly point to it, for example moving `connectors` first when the session is far over the connector limit and people are hitting usage limits. Say why you moved it.
4. If a finding points to a module that is not part of this run, say so and offer to cover it at the end.
5. Offer the optional `content` module only if the person brought up marketing, content or visibility themselves.
6. If the person is not an owner or admin, say which later steps will need one, so they can line that person up.

### Done when

- The person has seen the findings table, each finding has a difficulty and a module, and they have agreed or corrected it.
- The order of the modules is agreed.

### Mark blocked when

- Too many answers in the first three steps are "not known" to say anything useful. List what is missing and who can answer it.

### Summary to report

State how many findings there are at each difficulty and the agreed order, using module ids. Example: "Seven findings: four easy, two medium, one hard (heavy connectors for the main services). Agreed order: connectors, processes, skills, foundations."
